Phase 3 is the comfortable half (PRD §risks: "scope creep into the platform half"), so every task names the engine or write path it renders and adds no rule of its own. Every page is under `src/app/o/[org]/` behind `requireOrg`, every mutation is a `'use server'` action with an `ActionSpec` so the INV-01..04 harness finds it, and every page shows the fixture-seed numbers on the demo org.

Phase 3 exit bar (PRD P0-7 + success metric): the editor shows `ACC-101 -> ACC-201 -> ACC-101` for E-01 before the publish button is pressed; a learner page shows status per course, the minimal missing set and the shortest path with the satisfied-leaf reasons; a gradebook page shows the exact rational on request next to the rounded grade; a drip calendar lists release days, completions and refused attempts; axe clean in light and dark; e2e drives each page on the seeded org; CI green.

- [ ] **3.0 Demo org and actions scaffold.** `seed:demo` (template) gains the fixture school: `seedFixtures(fx, 'demo-school')` with the demo owner as a member, so `/demo` lands on a populated book. `tests/fixtures/app.ts` `seedApp` returns one row of each clone model (the INV harness needs refs for `ref('<model>')` inputs). Permissions: which roles may publish (owner/admin), enter scores (admin + `scorekeeper`, the template's D-21 role), complete items (member = learner). *Acceptance:* INV-01..04 green with the new actions; `seedApp` rows exist in both harness orgs.
- [ ] **3.1 Catalog editor with live cycle check (PRD P0-7, G1–G5).** `/o/[org]/catalog`: the current version (label, hash, course table with status and prerequisite expression), a draft edit form (set prerequisite / set status / add course) that re-runs `applyEdit` + `validateCatalog` **client-side** on every change (the engine is pure and ships to the browser unchanged; `src/graph/` has no Node imports) and renders every error and every cycle path before the publish button is enabled; publish is a server action calling `publishEdit`, which re-runs the check server-side (never trust the client verdict) and shows the attempt's verdict and grandfather count. The attempt history list (`PublishAttempt`) is the editor's "why was this refused" record. *Acceptance:* E-01 shows `ACC-101 -> ACC-201 -> ACC-101` with the button disabled; E-04 publishes and shows "17 grandfathered"; the e2e types the E-01 edit and reads the cycle path from the page.
- [ ] **3.2 Learner path view (PRD P0-7, G6–G8, P2).** `/o/[org]/learners/[code]`: status per course from `eligibilityFor` (UNAVAILABLE / COMPLETED / ELIGIBLE / BLOCKED with the missing set), the target certificate's progress and shortest path from `pathFor` with the reason for each satisfied leaf (`PASSED` / `EQUIVALENT:<by>` / `WAIVER:<reason>`), the enrolled version named on the page, and an explicit "re-evaluate against version …" control that shows both answers side by side (`reevaluate`, O-7) and changes nothing. Completion entry (PASS/FAIL, day) is a server action on `recordCompletion`. *Acceptance:* L-0001's page shows `expected_progress.csv`'s path; a GRANDFATHERED enrollment shows its flag and missing set and still shows the enrolled-version answer.
- [ ] **3.3 Gradebook per cohort (PRD P0-7, S2–S9).** `/o/[org]/cohorts/[code]/grades`: scores, late-adjusted scores, dropped items, category fractions, the final grade and letter from `gradeFor`, with the exact rational (`exactText`) shown on hover/expand (O-8: display may show two decimals of the exact rational; the fraction is always available); flags as a column. Score entry and correction are server actions on `recordSubmission` / `correctScore` (reason required); the row history (superseded rows) is visible per cell. *Acceptance:* C-ACC101-F26 renders 106-row-consistent values (spot: L-0076 6960, fails, `DROPPED:HW1` — GS-03's tie); a correction shows old and new with the reason.
- [ ] **3.4 Drip calendar per cohort (PRD P0-7, R1–R3).** `/o/[org]/cohorts/[code]/drip`: items by release day (`releaseDay`), per-learner completions (`ItemCompletion`), and the refused attempts from the audit log (`item.refused` rows with their verdict), course progress per enrollment from `courseProgressFor`. Item completion is a server action on `completeItem`. *Acceptance:* L-0003 in C-ACC101-F26 shows 4 of 9 done (4444) and its NOT_RELEASED attempt(s) listed with the day and the release day.
