# Coursework — Domain Brief (prerequisite graph, gradebook, drip, derived progress)

The source for vocabulary, the synthetic school, the two pure engines' rules, the golden cases and the kickoff measurements. Every rule code in §4–§6 is implemented in `tools/courselib.py`; every golden case in §7 is asserted by `tools/golden_answers.py` (ends with `OK`); every number in §8 is printed by `tools/reference_graph.py` and `tools/reference_grades.py` on the frozen fixtures in §9. Scores are integer hundredths of a percent (**hp**: `8550` = 85.50%); weights are basis points (**bp**, a scheme's categories sum to 10000); days are `YYYY-MM-DD` strings. Items marked **[verify]** are conventions, not facts, and have a D or O entry in `decisions.md`.

## 1. Product scope

A small professional training school ("Coursework", synthetic): 40 courses in six tracks (ACC accounting, DAT data, MGT management, PRJ project, SEC security, WRT writing), 36 published, 2 draft, 2 retired; 7 certificates composed of course sets; 300 learners with 1,352 course-level completion events (1,164 passes) since 2025; 16 fall-2026 cohorts with drip-released content; 4 of those cohorts graded under 2 published schemes. The lesson is the graph (prerequisites as a DAG with cycle detection, eligibility, shortest path) and the arithmetic (weighted grades in exact rationals rounded once); progress is never stored.

Left out: payments, video hosting, discussion forums, proctoring, accreditation claims, transcripts as legal documents, SCORM/LTI, email sending.

## 2. Vocabulary

| Term | Meaning here |
|---|---|
| Course | A unit with a code (`ACC-201`), title, status `DRAFT` / `PUBLISHED` / `RETIRED`, and a prerequisite expression. |
| Prerequisite expression | `null`, a course code, or a group `{"all":[…]}` / `{"any":[…]}` whose children are codes or groups of the other kind; groups nest at most two deep (G1). "C requires (A and B) or D" is `{"any":[{"all":["A","B"]},"D"]}`. |
| Leaf | A course code inside an expression. Edge `L → C` exists for every leaf L of C's expression, ALL and ANY alike (G2). |
| Catalog version | An immutable set of courses + equivalencies + certificates, content-hashed (V1). `cat-v1` is the kickoff version. |
| Draft edit | A list of operations (`set_prereq`, `set_status`, `add_course`) against a version; publishing it is `ACCEPT` (a new version) or `REJECT:<code>`. |
| Equivalency | Catalog data: passing course B satisfies leaf A (`{"satisfies":"ACC-101","by":"ACC-100","reason":"EQUIVALENT_COURSE"}`). |
| Waiver | Learner data: leaf A is satisfied for learner L with a reason code (`TRANSFER_CREDIT`, `PLACEMENT_TEST`, `INSTRUCTOR_WAIVER`, `PRIOR_LEARNING`). |
| Completion event | Course-level `PASS` / `FAIL` for a learner on a day, tagged with the catalog version it was evaluated under. Only `PASS` satisfies a leaf. |
| Eligibility | For a learner and a course: `COMPLETED`, `ELIGIBLE`, `BLOCKED` (with the minimal missing set, G7) or `UNAVAILABLE` (course not published). |
| Certificate | A code and a set of required courses. Certificate progress = satisfied required courses / required, as bp, floor (P2). |
| Shortest path | The fewest additional courses whose passing completes a certificate with every prerequisite satisfied (G8). |
| Cohort | One run of a course: start day, content items with release offsets, enrolled learners, optional grade scheme. |
| Content item | A lesson or exercise in a cohort; released on `start_day + offset_days` (R1). |
| Grade scheme | Categories with bp weights and drop-lowest-N, a late rule, an extra-credit cap, a missing-work flag, a pass threshold in hp and a letter-band table (S1). |
| Assignment / submission | An assignment has a category, `points_possible`, a due day and an extra-credit flag; a submission has `score_hp` (percent of possible, in hp) and a submitted day. No row = missing. |
| Derived state | Course progress, certificate progress, eligibility and grades are computed from events and a catalog version on every read and never stored as truth (P1). |

## 3. Synthetic school (fixtures)

Generated by `tools/build_fixtures.py --seed 20261025` (§9). Learner names come from two 30-name lists; emails are on `example.org`. Nothing is a real person or a real institution.

**Catalog `cat-v1`** (hash `32978f4b…`, GG-20): 40 courses, 56 edges. Structures built on purpose: a **diamond** (`DAT-401` requires `DAT-202` and `DAT-302`; both reach `DAT-201`); **nested ANY in ALL** (`DAT-202` = all[`DAT-102`, any[`DAT-101`, `DAT-201`]]; `ACC-302`, `DAT-302`, `MGT-202`, `PRJ-302`, `SEC-302`, `SEC-401` likewise); **flat ANY** (`DAT-201`, `MGT-301`, `PRJ-301`, `WRT-202`); a **retired course with an equivalency** (`ACC-100` → `ACC-101`, `SEC-100` → `SEC-101`); two **draft courses** (`ACC-303`, `DAT-303`) that published courses may not require. 7 certificates; `CERT-DATA-ADV` is the single course `DAT-401`, nine courses deep from nothing.

**15 draft edits** (`draft_edits.json`), 11 invalid by design: E-01 2-cycle · E-02 3-cycle whose closing edge is one branch of an ANY · E-03 self-reference · E-05 published course requiring a DRAFT · E-06 ANY whose one branch is a cycle (the other branch is fine — still rejected) · E-08 unknown code · E-09 depth 3 · E-10 empty group · E-12 retiring a course three published courses require · E-13 the diamond closed into a cycle · E-14 two independent cycles in one edit. Accepted: E-04 (tightens `WRT-202` from ANY to ALL; 17 in-progress learners grandfathered), E-07 (publish `DAT-303`), E-11 (`ACC-202` gains `ACC-102`; 6 grandfathered), E-15 (adds `ACC-203`; 41 courses).

**Learners:** 300; each has a target certificate and a completion history produced by a prerequisite-respecting walk (a course is attempted only when eligible at that time; 85% of attempts pass). 24 learners hold one waiver each on a 100-level course; 11 passed the retired `ACC-100` and 13 the retired `SEC-100` (equivalency traps). 70 learners have already satisfied every course of their target certificate; 125 are under 25%.

**Cohorts:** 16, starting 2026-08-31 … 2026-10-13, 9 content items each at offsets 0, 0, 3, 7, 10, 14, 17, 21, 28 days; 341 enrollments (a learner is in at most two). 2,051 item-completion events, of which **154 fall before the item's release day** (R2 trap) and **12 come from learners not enrolled** in that cohort (R3). The accepted events derive each enrollment's course progress.

**Gradebook:** 4 graded cohorts, 35 assignments, 806 submissions. Traps built in: `C-DAT102-F26` has **no Project assignment** (S6 redistribution for all 26 learners); `C-ACC101-F26` has an **extra-credit** homework (S7; 6 learners hit the cap), **three learners whose HW3 is 35.00% six days late** (penalty 50.00 floors to 0, S3), and **one learner with HW1 and HW3 tied at 70.00% on different point values** (S5 tie, L-0076: 69.60 and fails; dropping the other would give 70.00); `C-WRT101-F26` uses the `EXCLUDE` missing rule, so 7 learners with no participation row **empty a category** (S4 + S6). `SCH-BAD` has weights summing to 9900 (S1).

**Not generated (say so in any write-up):** incomplete/withdrawn grades, regrades, re-takes with grade replacement policies, co-requisites, prerequisites by minimum grade ("B or better"), time-limited prerequisites, cohort transfers, concurrent catalog versions for one learner, instructor overrides of a final grade. Each is a seam, not a feature.

## 4. Prerequisite graph (`src/graph/`, pure)

| ID | Rule |
|---|---|
| G1 | **Closed expression vocabulary.** `null` · `"CODE"` · `{"all":[…]}` · `{"any":[…]}`. A group has ≥ 1 child; a nested group must be of the other kind (`PREREQ_SAME_KIND`); groups nest at most two deep (`PREREQ_DEPTH`); every code exists in the version (`PREREQ_UNKNOWN`); a group is empty → `PREREQ_EMPTY_GROUP`; any other shape → `PREREQ_SHAPE`. A self-reference is not an expression error; it is a 1-cycle (G3). No free-form expressions, no `eval`. |
| G2 | **Edges are structural.** For every course C and every leaf L of its expression, there is an edge L → C ("L before C"), regardless of ALL or ANY, regardless of status. The graph covers every course in the version, drafts included. |
| G3 | **Cycle detection on publish.** Strongly connected components (Tarjan; nodes and successors visited in lexical order). A component is a cycle if it has > 1 member or one member with a self-edge. For each, the *reported path* starts at the lexically smallest member s, follows a breadth-first search inside the component expanding successors in lexical order, and closes on the first edge back into s: `s → … → u → s`. A self-reference reports `X → X`. Components are listed by smallest member. Any cycle → `REJECT:CYCLE` for the whole edit; an ANY branch that closes a cycle is still a cycle (E-06), because an unsatisfiable branch is a design error, not an alternative. |
| G4 | **Topological order** by Kahn's algorithm with a min-heap on course code: among ready courses the lexically smallest goes first. Drafts and retired courses are ordered too. |
| G5 | **Publish checks, in stage order:** expression errors (G1) → `PREREQ_UNPUBLISHED` (a PUBLISHED course has a leaf that is not PUBLISHED; retiring a course that published courses require fails here, naming every dependent) → `CYCLE` (G3). Every error is reported, sorted by stage, code, detail; the headline is `REJECT:<first code>`. Equivalencies and certificates must reference known codes (`EQUIV_UNKNOWN`, `CERT_UNKNOWN`, stage 0). |
| G6 | **A leaf is satisfied** for a learner, in this precedence and with this reason: `PASSED` (a PASS completion of the leaf) → `EQUIVALENT:<by>` (a PASS of a course the catalog says is equivalent; several `by` courses are tried in lexical order) → `WAIVER:<reason>` (a waiver row for that learner and leaf). A FAIL satisfies nothing. Satisfaction does not depend on the leaf's status: a retired course already passed still counts. |
| G7 | **Minimal missing set.** Leaf: `[]` if satisfied, else `[leaf]`. ALL: the union of the children's missing sets. ANY: `[]` if any child's missing set is empty; otherwise the child's missing set with the **fewest codes**, ties broken by lexicographic comparison of the sorted lists. Always sorted. "Minimal" is leaf-count under the expression, not depth of what is missing (GG-13). **Eligibility status** precedence: `UNAVAILABLE` (course not PUBLISHED) → `COMPLETED` (learner passed it) → `ELIGIBLE` (missing empty) → `BLOCKED` (missing listed). |
| G8 | **Shortest path to a certificate.** Over the upstream cone of the certificate's courses, enumerate every combination of ANY-branch choices (depth ≤ 2 keeps this small: 16 combinations at most on `cat-v1`); for each, the needed set is the fixpoint closure of unsatisfied certificate courses and their unsatisfied leaves under the chosen branches; take the smallest set, ties by lexicographic comparison of the sorted lists; return it in topological order (G4). Exact, not greedy: on `CERT-DATA-ADV` two branches tie at 9 courses and the lexical rule picks the ACC branch (GG-17). |
| G9 | **Retroactive block = report, never block.** For an accepted edit, every enrollment with status `IN_PROGRESS` whose learner is `ELIGIBLE` under the old version and `BLOCKED` under the new one is listed as `GRANDFATHERED` with the new missing set. The learner's enrollment stands (V3). Sorted by learner, course. |

## 5. Drip release, derived progress, catalog versions

| ID | Rule |
|---|---|
| R1 | **Release day** = `start_day + offset_days` by integer calendar arithmetic (`days_from_civil` / `civil_from_days`, Hinnant's algorithm, ported as integers). No `Date`, no timezone. An item is released on its release day inclusive. |
| R2 | **An item completion before its release day is `REJECT:NOT_RELEASED`.** Compared as day numbers; no clock is consulted — the event carries its day. |
| R3 | An item completion by a learner not enrolled in that cohort is `REJECT:NOT_ENROLLED`; an unknown item code is `REJECT:UNKNOWN_ITEM`. Checked in this order: enrollment → item → release. |
| P1 | **Progress is derived, never stored.** Course progress for an enrollment = accepted item completions / items in the cohort, as bp, floor. Certificate progress = satisfied (G6) required courses / required, as bp, floor. `progress:verify` recomputes both for every learner from events and compares to `expected_*`. |
| P2 | Progress is evaluated against the **catalog version the learner enrolled under** (`enrolled_catalog_version`); re-evaluation against a newer version is an explicit action that records both answers. Phase 1 has one version. |
| V1 | **Catalog versions are immutable and content-hashed:** SHA-256 of canonical JSON (sorted keys, no whitespace) of `{certificates, courses, equivalencies}`; the version label is outside the hash. Publishing an accepted edit creates a new version; nothing is edited in place. (Adjuster's pattern.) |
| V2 | A completion event records the catalog version it was evaluated under. A learner's eligibility is read against their enrolled version unless re-evaluated (P2). |
| V3 | Grandfathering (G9) is a flag on the report and, in Phase 2, on the enrollment; it never changes a completion or an eligibility answer under the enrolled version. |

## 6. Gradebook (`src/grades/`, pure)

| ID | Rule |
|---|---|
| S1 | **Scheme publish check.** Weights in bp sum to exactly 10000 (`REJECT:WEIGHTS_SUM`, with the sum); each weight > 0; `drop_lowest` ≥ 0; unique category codes; bands strictly descending with the last at `min_hp` 0; `pass_threshold_hp` in 0..10000; `missing` ∈ {`ZERO`, `EXCLUDE`}. |
| S2 | **Units.** `score_hp` is an integer percent-of-possible in hundredths; `points_possible` is an integer. Earned points for an assignment = `possible × adjusted_hp / 10000` as an exact rational. No float anywhere under `src/grades/`. |
| S3 | **Late penalty** = `min(days_late, max_days) × per_day_hp`, subtracted from `score_hp`, **floored at 0** (`PENALTY_FLOORED` when a positive score reaches 0). `days_late` = submitted day − due day in calendar days; ≤ 0 is on time. `SCH-STD`: 10.00/day, max 5 days. |
| S4 | **Missing work.** No submission row: with `missing = ZERO`, the assignment counts with `adjusted_hp = 0` (`MISSING_ZERO:<code>`); with `EXCLUDE`, it leaves both numerator and denominator. A missing extra-credit assignment is always excluded and never flagged. |
| S5 | **Drop-lowest-N** per category over regular (non-extra-credit) assignments: sort by `(adjusted_hp, code)` ascending and drop the first N. **Tie: the lexically smaller code is dropped.** It matters when point values differ (GS-03: 9233 vs 9250). Flag `DROPPED:<cat>:<codes>`. |
| S6 | **Category ratio** = Σ earned / Σ possible over the kept regular assignments (points-weighted within the category). A category with no kept assignment is **empty** (`EMPTY_CATEGORY:<cat>`) and its weight is **redistributed proportionally**: final = Σ(w_i × ratio_i) × 10000 / Σ w_i over non-empty categories. All empty → 0, `NO_GRADED_WORK`. |
| S7 | **Extra credit** adds its earned points to the category numerator only. Final = min(final_with_EC, final_without_EC + `extra_credit_cap_hp`); when the cap binds, `EC_CAPPED`. Final is then clamped to [0, 10000]. |
| S8 | **Rounding once.** Every intermediate value is an exact rational (Python `Fraction`; TypeScript integer numerator/denominator with `BigInt`). The final grade in hp is rounded **half-up** (`floor(x + 1/2)`) exactly once. Pass = `final_hp ≥ pass_threshold_hp` on the rounded value, so 6999.5 passes at 7000 and 6999.2 does not (GS-13/14). The exact rational is reported next to the rounded value. |
| S9 | **Letter** = the first band whose `min_hp ≤ final_hp`, bands descending. Bands are scheme data, not code. |
